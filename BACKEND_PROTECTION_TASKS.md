# Backend protection tasks

Each item is completed separately. Local checks do not establish hosted readiness.

1. **Environment isolation: local code and tests complete; hosted setup pending.** Explicit local/staging/production configuration, Project ID pinning, administrator-owned server marker, release-only production opt-in and persistent test labels. Startup displays verification progress and a safe retry on failure. All 271 Flutter tests and 13 migrations/access checks passed locally. Hosted project assignment and real cross-environment checks remain pending. Read `supabase/ENVIRONMENTS.md` before using a connected build.
2. **Photo lifecycle: local code and tests complete; hosted setup pending.** Immutable upload tickets/fingerprints, retained-selection retry, stale-screen and in-flight compare-and-set checks, locking evidence RPCs and scoped Storage cleanup are implemented in migration 014 and the connected flow. Provider reload performs bounded best-effort cleanup; an administrator-only unattended worker defaults to read-only dry run and has not been deployed/scheduled. Unknown historical files are not auto-deleted. All 282 Flutter tests, 14 migrations/access checks, five mocked worker tests and release Web build passed. Actual Storage bytes/metadata, device images, multi-session races and recurring cleanup require staging verification. See `supabase/PHOTO_UPLOAD_LIFECYCLE.md`.
3. **Pagination: local code and tests complete for connected bookings, booking chat and status history; hosted verification pending.** Migration 015 provides participant-scoped cursor pages (20 by default, 50 maximum), timestamp/UUID tie-breakers and an independent Owner summary aggregate. Load-older failures preserve loaded records and drafts; feed tests cover duplicate taps, late replies, realtime merges/deletions and reconnect resets. All 298 Flutter tests, 15 local migrations/access checks and release Web build passed. This does not yet paginate the property/provider directory or prove hosted Realtime behavior. See `supabase/PAGINATION.md`.
4. **Subscription lifecycle: local code and tests complete; hosted/device checks pending.** Current-route/resumed-only activation, awaited channel/socket teardown, serialized restart, fresh booking-status checks and account-boundary cleanup are implemented. Twenty repeated feed cycles and twenty real-SDK loopback joins/leaves show no registry growth; auth/navigation fixtures verify old routes and late responses cannot reopen the previous session. All 318 Flutter tests and the release Web build passed. These tests do not certify hosted Realtime/RLS or mobile OS background behavior. See `supabase/SUBSCRIPTION_LIFECYCLE.md`.
5. **Caching and compression: local code, SDK loopback and Chrome image-output checks complete; hosted/real-device checks pending.** A session-bound memory cache holds at most 12 MiB/24 entries, coalesces reads, limits in-flight cache loads and expires photos after two minutes/reference services after five. Private photos require a fresh participant/pointer read even on a cache hit. Account changes, replacement and memory pressure invalidate data. Actual JPEG/PNG pixel processing normalizes orientation, strips source metadata and produces JPEG up to 1600px/1 MiB before upload; native heavy work uses an isolate and Web uses native canvas codecs. All 346 native Flutter tests, 12 Chrome HTML-renderer image tests and release Web build passed. This is not offline mode, whole-process RAM certification, server-side byte inspection or a real-device performance/quality sign-off. See `supabase/CACHING_AND_COMPRESSION.md`.

6. **Test-data provenance and review: local tooling/database checks complete; hosted setup pending.** Migration 016 registers explicitly provisioned, new synthetic Owner/Provider accounts in staging-only runs. Atomic, retry-safe fixtures create labelled properties, slots and one priced Pending request, without overwriting existing business identities or inventing completion/payment/evidence. The Node tool defaults to dry run, requires explicit project confirmation for creation and provides read-only dependency counts/review reminders; mixed-account bookings are flagged. Full business-data/account purge is intentionally not implemented or approved. See `supabase/TEST_DATA_MANAGEMENT.md` for manual Auth provisioning and staging checks. Never auto-delete evidence, histories or accounts in production.
